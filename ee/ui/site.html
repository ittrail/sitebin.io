Addresses

A domain is attached once its DNS proves it belongs to this site: a TXT record with the token shown after you add it, or a CNAME at the domain pointing at this site's own address. Route it with A → your server IP or that CNAME ( also works for routing, but only the site's own address counts as proof). The certificate is issued automatically on the first visit.

A domain can redirect to another of this site's domains — example.de → example.at, www.example.com → example.com — with the status code you pick; the path and query are kept, and the redirect is answered here, on the domain's own certificate. Once a domain serves the site, its generated address can be switched off or redirected too.

A domain can carry a path — example.com/docs — to serve this site under it while your other projects serve the rest of the domain; the longest matching path wins. A domain another of your projects already holds needs no new record. The site must be built for its path (Astro: base: '/docs'), or it will not find its own files; a warning appears here when it is not.

An app has one generated address per HTTP port its compose file lists under http:, and each domain serves the port you pick. A port's generated address can be switched off once a domain serves that same port. A domain whose port leaves the file stays attached and serves nothing until you point it at another.

Forms

This site's plan includes no forms.

A form mails what visitors submit to its recipient, who confirms once by email before the form goes live. Paste its snippet into any page of this site: it is plain HTML and needs no script unless the captcha is on. Every mail lays out the fields, carries the attachments, and includes a submission.json for machines.
Forms are not available on this instance.

# Site tags, tag groups and colours: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every site can carry tags (core). "My account" filters its site list
by tags in group blocks and manages groups, colours, renames and deletes
(enterprise).

**Architecture:**
- **Core (MIT).** `store.Meta.Tags` is validated by one function,
  `store.CleanTags`. It travels the same path as the site name: the JSON API
  settings, MCP `Settings`, the edit page, and the `ext.SiteInfo` and
  `ext.SiteService` seam.
- **Enterprise.** A per-account tag registry, `accounts/<id>/tags.json`, holds
  groups, colours and display spellings. A pure filter function turns the URL
  query into a selection. The dashboard and the new `/account/tags` page are
  server-rendered forms and links. No new script runs.

**Tech Stack:** Go (stdlib `net/http`, `html/template`), embedded static JS
for the edit page, PowerShell e2e scripts.

**Spec:** `docs/superpowers/specs/2026-11-03-site-tags-design.md`.
Executors read it. Its "Shared sites" section is **not** in scope here: it
lands with the ownership plan. The precedent for every core step is the
site-names change (`docs/superpowers/specs/2026-09-24-site-names-design.md`,
commit c6ae71c); its tests live in `internal/store/sitename_test.go`,
`internal/httpapi/sitename_test.go` and `ee/sitenames_test.go`.

## Global Constraints

- **Branch:** work on `feat/site-tags` in `Sitebin/`, and on `content/site-tags`
  in `Sitebin-Website/`. Merge to `main` only in the ship task.
- **Verification for every Go task:** `go vet ./...`, `go test ./...` **and**
  `go test -tags ee ./...`, all green.
- **Stored data:** `meta.json` field `tags` is `omitempty`, and a missing
  field is untagged. No migration.
- **The tag rules**, enforced by `store.CleanTags` and nowhere else:
  - surrounding space trimmed, inner runs of space collapsed to one;
  - control characters and commas **refused, not stripped**;
  - 1–30 runes per tag, at most 10 tags per site;
  - case-insensitive duplicates merged, keeping the first spelling;
  - stored order case-insensitively alphabetical.
- **Exact error messages** (user-safe, shown as they are):
  - `store.ErrBadTag` = `"a tag is 1 to 30 characters of plain text, without commas"`;
  - `store.ErrTooManyTags` = `"a site carries at most 10 tags"`.
- **Identity:** `store.TagKey(s) = strings.ToLower(s)`. Every comparison goes
  through it.
- **API:** `"tags"` is always present in site payloads (`[]` when untagged).
  **MCP:** `tags` is `omitempty` in `SiteResult` and `SiteSummary`.
- **Private:** Caddy, authz, the viewer and the admin register never read or
  show tags.
- **Registry limits:** at most 20 groups and 200 registry tags per account.
  Group names follow the single-tag rule and are unique
  case-insensitively.
- **Palette** (ids stored, hex only in CSS): `blue #5b8cff`,
  `green #5ecf8a`, `amber #f5b84d`, `red #f26d6d`, `violet #a98bff`,
  `teal #3fc6c6`, `pink #ff86c8`, `grey #97a3b8`. Unknown id → grey.
- **Dashboard CSP unchanged:** `script-src` stays `copyScriptCSP`.
  Autocomplete is an HTML `<datalist>`.
- **E2E scripts stay pure ASCII.** Write `--`, never `—`, and use no umlauts
  in tag values there.
- **Commits:** lowercase conventional prefix; the subject is a sentence
  about behaviour; end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **A tag name containing HTML or quotes** (`<b>x</b>`, `"a"`) must render
   escaped everywhere on the dashboard, the manage page and the edit page. A
   reasonable person expects text, not markup. Pinned in Task 8 and Task 5.
2. **A non-ASCII tag in a filter link** ("Müller GmbH") must round-trip
   through the URL to the same selection. A bookmark of the filter must keep
   working. Pinned in Task 7.
3. **A stale filter bookmark** (a tag that was renamed or deleted, a group id
   that is gone) must show the rest of the selection, or All. It must never
   be an error or a confusingly empty list. Pinned in Task 7.
4. **An unreadable or corrupt `tags.json`** must not take the dashboard
   down. The sites render, with tags ungrouped and grey, and the error is
   logged. Pinned in Task 8.
5. **An API tag write racing an account-wide rename** must not lose either
   change. That is why the seam edits under the site lock (Task 3). Pinned in
   Task 3 and Task 9.

### Task 7: The filter, as a pure function (enterprise)

**Files:**
- Create: `ee/tagfilter.go`, `ee/tagfilter_test.go`

**Interfaces:**
- Consumes: `account.TagRegistry`, `store.TagKey`.
- Produces:
  ```go
  type tagSelection struct {
      Untagged bool
      Tags     map[string]bool // tag keys
      Groups   map[string]bool // whole groups, by id
  }
  func parseTagSelection(q url.Values, reg account.TagRegistry, inUse map[string]bool) tagSelection
  func (s tagSelection) Query() string                 // "" for All; stable order
  func (s tagSelection) ToggleTag(key string) tagSelection
  func (s tagSelection) ToggleGroup(id string) tagSelection
  func (s tagSelection) WithUntagged() tagSelection    // clears tags and groups
  func (s tagSelection) Matches(siteTags []string, reg account.TagRegistry) bool
  func (s tagSelection) Summary(reg account.TagRegistry, matched, total int) string
  ```
- **Query shape:** `t=<tag key>` (repeated), `g=<group id>` (repeated),
  `untagged=1`. `parseTagSelection` drops tag keys not in `inUse` and in no
  registry entry, and group ids not in the registry (Review Focus 3).
  `untagged=1` beside tags or groups means only Untagged.
- **Matching:** every facet must match.
  - A facet is one group with something selected in it: a site matches it
    when it carries any selected tag of that group, or, if the whole group is
    selected, any tag of the group.
  - Each selected ungrouped tag is its own facet.
  - A tag whose group id is gone counts as ungrouped.
- **Summary format**, exactly:
  - `"2 of 8 · (Müller GmbH or Bäckerei Huber) and mockup"`;
  - a whole group is its name (`"Kunde"`);
  - one-tag facets have no parentheses;
  - Untagged is `"3 of 8 · untagged"`;
  - All is `""`.
  - Groups appear in alphabetical order, then ungrouped tags; inside a facet,
    alphabetical.

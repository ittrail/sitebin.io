# Custom domains with a path — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A custom domain may carry a path (`morgenfertig.at/demos/kunde123`), so independent Sitebin projects of one account share a host, each served by Sitebin directly.

**Architecture:** The address string `host` / `host/path` stays the identity in `meta.json` (`CustomDomains`, `DomainClaims`, redirects, targets), the API and MCP. One seam maps an address to its index link (`domain-index/<host>` or `path-index/<host>/<enc>`), so attach/detach/delete/lookup change in one place. authz resolves host + longest path to (site, mount) and tells Caddy, through internal headers, which site folder to serve and which prefix to strip; containers get the full path plus `X-Forwarded-Prefix`; `<mount>/_sitebin/*` is proxied to the backend with the mount, from which the backend resolves the site.

**Tech Stack:** Go 1.25 (stdlib `net/http`), Caddy v2 Caddyfile generated by `internal/caddygen`, vanilla JS edit page, PowerShell e2e against the real image.

**Spec:** `docs/superpowers/specs/2026-11-02-custom-domains-with-a-path-design.md`

## Global Constraints

- Path form: starts with `/`, no trailing slash, no query/fragment, no empty/`.`/`..`/`_sitebin` segment; segment chars `a-z 0-9 - _ . ~`; ≤ 8 segments; ≤ 200 chars; uppercase **refused**, not lowercased.
- Match: `p == path` or `p` has prefix `path + "/"`; longest wins; empty path matches all; case-sensitive; on the decoded, dot-cleaned path.
- Path addresses are custom domains only — never on the view domain, the base domain, or any reserved domain.
- A path address counts as one custom domain (per-site `QuotaDomains`, licence `max_custom_domains`); names in the owner's verified zone are exempt.
- Sharing a host: only one owner; a different owner's verified address on the host → `ErrDomainTaken`; a voucher is an address of the same non-empty owner on the host that is verified, `!ViaHost`, held by its own proof.
- Shared revocation clock: `revokeAfter` (72 h) from the earliest `FailingSince` of the failing vouchers, or from the first check that finds no voucher.
- Containers: full path passed through, `X-Forwarded-Prefix: <mount>` (absent at the root). Client copies of `X-Forwarded-Prefix` are removed.
- Static/file viewer under a mount: prefix stripped; bare prefix → `308` to `<mount>/`, query kept.
- `<mount>/_sitebin/*` belongs to Sitebin for every site kind.
- View-password cookie path under a mount: `<mount>/`.
- Community build: unchanged (custom domains stay refused there).
- `meta.json` additions are `omitempty`; sites without them read as today.
- `e2e/*.ps1` stay pure ASCII.
- Commits: lowercase conventional prefixes, behaviour sentences, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Run both `go test ./...` and `go test -tags ee ./...`, plus `go vet ./...`, before every commit.

## Review Focus

1. **A path spelling that makes authz and Caddy disagree** (`%2e%2e`, `//`, percent-encoded letters, `/demos/kunde123/../x`): a reasonable person expects that no spelling serves a file from a site other than the one authz checked, and that a view password on a mounted site cannot be skipped. → Task 5 (authz unit tests) and Task 10 (e2e against real Caddy).
2. **A host whose root project is deleted while paths live under it:** the paths must keep serving, then follow the shared 3-day clock. → Task 3 tests `TestReconcileViaHostSharedClock`, `TestDeleteRootKeepsPathAddresses`.
3. **An existing plain custom domain and an existing container app** must behave byte-for-byte as before (no new stripping, no 404 at `/_sitebin/`, `/foo/_sitebin/x` still reaches a root container). → Task 5 `TestAuthzPlainDomainUnchanged`, Task 10 e2e.
4. **Removing an address over the API with a slash in it** (`DELETE /api/sites/{id}/domains/morgenfertig.at%2Fdemos`) must work through Caddy and Go's mux. → Task 8 `TestRemovePathAddressEncoded`, Task 10 e2e.
5. **Two projects of different accounts racing for one host** (one has a pending claim, the other attaches): the pending one is dropped, never attached beside it. → Task 3 `TestForeignOwnerRefusedAndPendingDropped`.

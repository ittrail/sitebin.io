Containers 


      

        The project runs what sitebin-container-compose.yaml in the site's root declares, and
        every change to that file restarts it — however you save it. Each root folder is a
        volume: upload your app into the folder a service mounts. A service lists the ports it speaks HTTP on
        under http:; each gets an address of its own, and which domain serves which port is set under
        Custom domains below — that never restarts the app.

Access

      

        
        

          
          
          
        

        
      

      

        
        

          Mount 

          Any username · password = your edit password.
          

            On plain HTTP: Windows Explorer and macOS Finder refuse to send
            the password over an unencrypted connection, so mounting fails with a 401. Use an
            HTTPS instance, or a client that allows it — rclone, WinSCP, Cyberduck,
            or curl. (Windows: set BasicAuthLevel to 2 and restart the
            WebClient service.)
          

        

      

      

        
        

          Connect 

          Username = your site's edit UUID · password = your edit password.
          

            Heads-up: plain FTP sends your password unencrypted — use it only on a
            trusted network (or an FTPS-configured instance). Clients: FileZilla, WinSCP, curl, rclone.
          

        

      

      

        
        

          
          
          
        

        
      

    


    

      
Custom domains

      

      

        
        
        
      

      

        A domain is attached once its DNS proves it belongs to this site: a TXT record with the token shown
        after you add it, or a CNAME at the domain pointing at this site's own address. Route it with
        A → your server IP or that CNAME ( also works for routing,
        but only the site's own address counts as proof). The certificate is issued automatically on the first visit.
        


        A domain can redirect to another of this site's domains — example.de → example.at,
        www.example.com → example.com — with the status code you pick; the path and query are kept,
        and the redirect is answered here, on the domain's own certificate. Once a domain serves the site, its
        generated address can be switched off or redirected too.
        


        A domain can carry a path — example.com/docs — to serve this site
        under it while your other projects serve the rest of the domain; the longest matching path wins. A domain
        another of your projects already holds needs no new record. The site must be built for its path (Astro:
        base: '/docs'), or it will not find its own files; a warning appears here when it is not.
        


        An app has one generated address per HTTP port its compose file lists under http:, and each
        domain serves the port you pick. A port's generated address can be switched off once a domain serves that
        same port. A domain whose port leaves the file stays attached and serves nothing until you point it
        at another.
